# Figure スキル

保存先: `~/.claude-plugins/figure/<project>/`

- 説明: `<YYYYMMDD-HHMM>-<トピック>.md`（例: `20261125-1530-plan-exec.md`）
- PR概要: `pr-<ブランチ名>.md`（`/` は `-` に置き換える。再実行時は上書きする）
- Artifact: 同じ名前で拡張子を `.html` にする

`<project>` は `git remote get-url origin` のリポジトリ名（失敗したら `basename $(pwd)`）。

---

## 呼び出しパターン

### `/figure [対象]`

1. 対象を決める。指定がなければ直前の説明を対象にする
2. 下の「図の作り方」に沿って、Mermaid 入りの md を保存先に書く
3. `mo <ファイル> --target <project>` で開く（サーバーが動いていれば既存のタブに追加される）
4. 返信は結論1〜2行と md のパスだけ。図の内容を文章で繰り返さない
5. 修正を頼まれたら同じファイルを書き直す（mo が自動で再読み込みする）

### `/figure pr`

1. `git diff <デフォルトブランチ>...HEAD` と `git log` で変更を把握する
2. PR概要の md を書く:
   - `## 概要`: 何を・なぜ変えたか（2〜3行）
   - `## 変更の前後`: 変更前と変更後の図（下の「変更の前後」のルール）
   - `## 変更点`: 主な変更ファイルと内容の箇条書き
   - `## 確認`: 実施したテスト・確認
3. `mo <ファイル> --target <project>` で開く
4. PR の本文に反映するかをユーザーに確認する。承認されたときだけ `gh pr create` / `gh pr edit --body-file` を使う

### `/figure artifact [対象]`

Mermaid では表しにくい図、論点を切り替えて見せたい図、人に共有したい図に使う。

1. artifact-design スキルを読み込む（Artifact を書く前に必須）
2. 下の「図の作り方」に沿って、SVG で図を描いた HTML を保存先に書く
3. Artifact ツールで公開する。修正時は同じファイルパスで再公開し、同じ URL を保つ
4. 返信は結論1〜2行と Artifact の URL だけ

論点が2つ以上あるときは、ボタンで論点を切り替え、選んだ論点の要素だけ枠を太くしてほかを薄くする（配置と色は変えない）。

## 図の作り方

### 基本

- **図を先に、文章は要点1行**: 言いたいことを1文に決め、図を描いてから図ごとの要点を1行書く
- **図だけで伝わる形にする**: 文章を消し、図中の文字も要素名と値だけにした状態で、位置・線・色から言いたいことが伝わるかを確かめる
- **見出しと図のタイトルは名詞で終える**: 読点（、）を入れず、結論の1文は見出しに入れない（例: 見出し「plan と exec をつなぐ保存ファイル」、要点「plan と exec は直接やりとりせず、ファイルを介してつながる」）
- **書く前に要素と矢印を一覧にする**: 埋まらない矢印や空欄はまだ分かっていない所なので、調べてから描く

### 図・表・文章の使い分け

- **図**: 3つ以上の要素の関係、状態や画面をまたぐ流れ、変更の前後
- **表**: 行と列に文章が入る対応（Markdown の表にする）
- **文章**: 2つのものの関係、分岐のない短い手順、単独の値

### 図の形の選び方

1. 読み手が何を判断するかから、問いを1つに決める。1枚の図が答える問いは1つ
2. 問いの分類を選ぶ

| 分類 | 見せること | Mermaid の例 |
|---|---|---|
| 構造 | 部品の構成、境界、依存の向き | flowchart |
| やりとり | 誰が誰に、どの順で、何を頼み何が返るか | sequenceDiagram |
| 状態と手順 | 状態の変わり方、処理の分かれ道 | stateDiagram-v2 / flowchart |
| データ | 何がどこに入り、どう流れ、どう関係するか | erDiagram / flowchart |
| 配置 | どこで動き、どの境界をまたいで通信するか | flowchart（subgraph） |
| 時間 | いつ何が起き、どの順で進むか | gantt / timeline |
| 変更 | 前後で何が変わり、どの順で移すか | flowchart を前後に並べる |
| 判断 | 案をどの観点で比べ、何を選ぶか | 表 / quadrantChart |

### どの図にも守ること

- **タイトル**: Mermaid は先頭の `---` で囲んだ frontmatter の `title:` に書く。変更の前後に関わる図は「今の〜」「直した後の〜」と分かるようにする
- **実物と名前の一致**: 要素の数・矢印・名前は実物（コード・画面・用語）に合わせる。作業中の呼び名や PR 番号を出さない
- **凡例**: 線の種類や色に意味を持たせたら凡例を置く
- **矢印の文字**: 1本の矢印に付ける文字は1か所にまとめる。渡すもの（呼び出し、データ名など）を書く
- **向き**: 向きが意味を持つ所は矢じり付きの線で描く

### 開発の図のルール

- **四角は1枚に6つまで**: 超えるときは範囲を分けるか、段階ごとの連作にする。収めるために要素や矢印を削らない
- **孤立した四角を描かない**: どの四角も矢印か入れ子でほかとつなぐ
- **同期は実線、応答や非同期は点線**
- **段階が増える構成は連作にする**: 同じ配置の図を段階ごとに並べ、1つずつ足す
- **変更の前後は同じ配置で色分けする**: 追加は緑、削除は赤の点線、変更は太線。変わらない所には印を付けない
- **状態の図は先に一覧で検証する**: 状態と遷移（出来事と条件）を書き出し、抜けと行き止まりを確かめてから描く

### 論点が2つ以上あるとき（md の場合）

1つの図の上に論点が2つ以上あるときは、論点ごとに別の図を描かず、同じ図を論点ごとに並べて強調だけを変える。図の中身が同じなら配置も同じになるので、読み手は変わった所だけを見ればよい。

1. 冒頭に論点の一覧を書く
2. 全体の図を1枚描く
3. 論点ごとに同じ図を描き、その論点の要素だけを `classDef focus stroke-width:4px` で太枠にし、ほかを `classDef dim opacity:0.3` で薄くする。色は図の中で意味を持つため変えない
4. 各図の下にその論点の結論を1行書く

論点ごとに描く物が違い、1つの図に収まらないときは使わず、論点ごとに図を分ける。

### 出す前に確かめる

- 図だけで伝わるか（文章を消しても言いたいことが読めるか）
- 要点の1行が図から読み取れることだけになっているか
- 数値や名前が本文と図で一致しているか
- 既存の図を直すときは同じファイルを書き換える（追記を重ねない）
